# v0.3.0

## Language changes

### Added

* Implementations using iris can now produce better errors. Iris itself also produces slightly more useful errors by default by pointing at the source file the error was caused in, if the information is available. ([#4](https://codeberg.org/LunarWatcher/iris/issues/4))
* Varadic functions (largely user-defined functions) now allow 0 arguments to be passed

### Fixed

* Prevent `capitalize` from throwing on an empty string
* Fixed `{% set object.key = "value" %}` assignment

## API changes

{% include "partials/api-changes.iris" %}

### Added

* Added `iris::CallbackError`, which should be thrown by end-user applications in custom callbacks. ([#10](https://codeberg.org/LunarWatcher/iris/issues/10))
* Added an optional argument for adding a filename to templates rendered without a file
  * This is used in error handling to make things clearer
* Added `importStack` and `filePathOrIdentifier` to `SourceLocation` ([#4](https://codeberg.org/LunarWatcher/iris/issues/4))
  * This allows implementing applications to create stacktraces
* Added explicit structured data on whether an `iris::IrisError` is a renderer error, parse error, or general error (happens outside the renderer and parser) ([#4](https://codeberg.org/LunarWatcher/iris/issues/4))
* Added support for vararg functions to accept 0 arguments
  * This is largely going to be useful with the new udata setup
* Added support for rendering with user-defined data. See the docs for custom callbacks for more info. ([#8](https://codeberg.org/LunarWatcher/iris/issues/8))

### Fixed

* Fixed a bug where DataObject failed to correctly copy Arrays, Strings, and Objects ([#9](https://codeberg.org/LunarWatcher/iris/issues/9))

### Removed

* Removed `parse_template`. Use `parse_file` instead, it's completely identical.
